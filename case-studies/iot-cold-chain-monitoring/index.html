The Situation

A Compliance Gap Waiting to Become a Crisis

A pharmaceutical distributor operating six temperature-controlled rooms across their Düsseldorf facility was relying on manual temperature logging — a clipboard and pen, twice per shift. Their GDP (Good Distribution Practice) audit had flagged this as a critical non-conformance: no continuous monitoring, no automated alerting, no tamper-evident digital log.

More critically: three months prior, a compressor failure over a weekend had gone undetected for 11 hours. The resulting stock loss was €47,000 and a near-miss on patient safety. One more incident of that magnitude would trigger regulatory intervention.

The question was never "do we need IoT monitoring?" — it was "can we deploy something production-grade in time for the re-audit?" Our answer: 4 weeks.
Deployment Timeline

4-Week Implementation Approach

Week 1

Site Survey & Hardware Specification

Cold room mapping, WiFi signal assessment, sensor placement planning. ESP32-S3 nodes with DS18B20 temperature probes and SHT31 humidity sensors specified per room profile.

Week 2

Firmware Development & Backend Provisioning

Custom ESP32-S3 firmware with MQTT over TLS. AWS eu-central-1 (Frankfurt) IoT Core provisioned. TimescaleDB time-series database deployed. Alert rule engine configured per room thresholds.

Week 3

Physical Installation & Network Integration

24 sensors installed across 6 rooms. Dedicated IoT VLAN provisioned. Redundant 4G failover configured — if WiFi drops, sensors switch to cellular without data loss.

Week 4

Dashboard Go-Live & Staff Training

React dashboard deployed. Alert escalation chains configured. Automated HACCP PDF report generation tested. Two-hour staff training completed. GDP audit documentation package delivered.

Technical Architecture

What Powers ADROIT SENSE™

Every sensor node runs custom ESP32-S3 firmware developed in C, publishing temperature, humidity, and battery telemetry every 30 seconds via MQTT over TLS 1.3 to AWS IoT Core. Edge-side anomaly detection runs directly on the microcontroller — if the MQTT broker is unreachable, the device stores readings locally and synchronises on reconnection. No data gaps.

The backend combines AWS IoT Core for message ingestion, TimescaleDB for time-series storage with automatic compression, and a Spring Boot alerting service that evaluates rules in real-time. Alerts are routed via SMS, email, and WhatsApp Business API — reaching the responsible person on whichever channel they respond to first.
