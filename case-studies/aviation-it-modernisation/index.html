Background

A mission-critical monolith serving global departures

The engagement began as a Java EE monolith modernisation — a platform originally built for a single airline that had grown, through acquisition and partnership, to serve multiple carriers simultaneously. Each airline had evolved its own configuration layer, data jurisdiction rules, and GDS integration preferences, creating a system that was simultaneously mission-critical and increasingly brittle.

Adroit Solutions was embedded directly within the client engineering teams at British Airways, Aer Lingus, and SITA — working alongside internal architects, not as an external consultant parachuted in for a handover, but as a sustained delivery partner across multiple release cycles.

Client Context

British Airways

Check-in and DCS for long-haul and short-haul operations at Heathrow. High-volume, strict SLA, Amadeus GDS primary.

Aer Lingus

Transatlantic and European routes. Sabre GDS integration. Custom pre-clearance data handling for US Customs and Border Protection.

SITA

Platform provider layer — multi-tenant DCS serving multiple smaller carriers. SaaS architecture requirements on top of existing infrastructure.

Engineering Challenges

Four problems that couldn't be solved incrementally

Legacy monolith load limits

The existing Java EE deployment could not scale horizontally. Peak departure waves — particularly bank holiday Monday morning short-haul — caused thread pool exhaustion and cascading timeout failures across check-in kiosks.

GDS integration brittleness

Synchronous SOAP calls to Amadeus and Sabre meant any upstream outage or latency spike propagated directly into check-in failures. A 30-second Amadeus timeout window was enough to stall an entire departure gate queue.

Zero-downtime deployment requirement

Airports operate 24/7. The existing deployment process required a full application restart — a 4-minute window acceptable at 2am, catastrophic at 06:30. Any modernisation had to deliver rolling deployments without passenger-facing impact.

Multi-jurisdiction data compliance

Passenger name records, API data, and advance passenger information had to be routed, stored, and purged according to UK, EU, and US regulatory requirements — per carrier, per route, with audit trails that could survive a regulatory review.

Solution Architecture

Strangler fig with an async GDS layer

Rather than a big-bang rewrite, we applied the strangler fig pattern — routing new check-in requests through Spring Boot microservices while the legacy monolith continued to handle existing sessions. Each service was independently deployable, with a Kafka async layer sitting between the application tier and GDS endpoints.

Kafka async GDS integration

All Amadeus and Sabre calls were moved off the synchronous request path. Check-in requests published a booking resolution event to Kafka; GDS responses were consumed asynchronously, with results written back to a Redis cache keyed on PNR. The check-in UI polled via a lightweight SSE endpoint rather than blocking on GDS latency. GDS outages became transparent to passengers.

Resilience4j circuit breakers

Each GDS adapter wrapped Resilience4j circuit breakers with per-airline configuration: different failure thresholds, half-open probe intervals, and fallback behaviours. Amadeus degradation triggered Sabre fallback for carriers licensed on both systems.

Rules engine for data jurisdiction

A declarative rules engine evaluated each PNR against route, carrier, and destination country to determine which data fields could be stored where, for how long, and what automated purge schedule applied. Audit events were published to an immutable append-only Kafka topic.

Technology Stack

Java 17 Spring Boot Apache Kafka Resilience4j PostgreSQL Redis AWS EKS Kubernetes Amadeus API Sabre GDS Terraform Helm

Deployment Approach

Rolling Kubernetes deployments

Zero-downtime blue-green via Kubernetes rolling update strategy. Health probes on /actuator/health before traffic shift.

Canary traffic splitting

New service versions received 5% of traffic via AWS ALB weighted target groups before full promotion. Automatic rollback on error rate threshold breach.

Infrastructure as code

All EKS clusters, RDS instances, and MSK Kafka brokers provisioned via Terraform. Environment parity guaranteed across dev, staging, and production.
