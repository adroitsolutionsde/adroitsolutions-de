Background

The Challenge: Airline IT That Cannot Fail

Global airlines operate on margins measured in seconds. A check-in system that drops for 10 minutes during peak departure blocks does not create inconvenience — it creates operational chaos: misconnected bags, gate hold delays, passenger compensation claims, and regulatory scrutiny. The architecture must hold at peak load, across continents, while staying synchronised with DCS (Departure Control Systems), GDS networks, and government border control APIs.

Adroit's senior architect was embedded directly into the core engineering teams at British Airways, Aer Lingus, and SITA — the global IT backbone powering hundreds of airlines. The mandate: redesign aging Java EE monolith architectures into resilient, horizontally scalable systems capable of surviving the post-COVID passenger surge.

"Mission-critical aviation systems have no margin for elegant failure. The architecture must eliminate single points of failure before the first line of code is written."
Technical Challenges

Four Problems That Could Ground Flights

01 — Legacy Monolith Load Limits

Java EE monoliths designed for pre-2010 passenger volumes unable to handle surge events (school holidays, bank holidays) without database connection pool exhaustion.

02 — GDS Integration Brittleness

Hard-coded synchronous calls to Amadeus and Sabre GDS systems creating cascading timeouts when upstream APIs degraded, taking check-in offline with them.

03 — Zero-Downtime Deployment

24/7 operations with no maintenance windows. Any deployment risked passenger data mid-transaction. Blue-green deployment strategy had to be retrofitted to legacy architecture.

04 — Multi-Jurisdiction Data Compliance

GDPR, US TSA data requirements, Australian border force APIs — passenger data handling rules that changed per route, per jurisdiction, per aircraft type.

Solution Architecture

What We Built

The architecture decision was to introduce an async messaging layer between the check-in frontend and the DCS backend — decoupling user-facing availability from backend processing. Apache Kafka served as the event backbone, with Spring Boot microservices replacing domain slices of the legacy monolith incrementally (strangler fig pattern).

GDS integrations were wrapped in circuit breaker patterns (Resilience4j) with local caching fallbacks — if Amadeus degraded, agents could still process check-ins from the last-known state with automatic reconciliation on recovery. This alone eliminated the most common cause of check-in outages.

Data jurisdiction rules were externalised into a rules engine, allowing per-route configuration without code changes — a critical enabler for adding new routes without engineering involvement.

Outcomes

Results Delivered

99.99% Uptime Achieved

System availability across two consecutive IATA peak seasons, including Christmas and August school holiday surges — the hardest load test real operations provides.

GDS Outage Immunity

Circuit breaker implementation meant three major Amadeus degradation events had zero impact on check-in availability — a first in the airline's operational history.

Deployment Frequency 10×

Blue-green deployment pipeline enabled production releases without maintenance windows, increasing release cadence from monthly to weekly.

Compliance Automation

Rules engine eliminated manual compliance configuration for new routes — reducing time-to-new-route from 3 weeks to 2 days.
